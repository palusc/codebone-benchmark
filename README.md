# codebone benchmark

Does codebone's generated context help your coding agent on a sample repository? Download this repo, give your
agent one prompt, and get a mechanically verified answer for your own model and machine.

The benchmark compares two fresh, isolated runs:

1. the agent solves the task with its normal repository tools;
2. the same agent solves the same task with an architecture map generated by codebone.

It then checks both implementations, records tokens and timing, includes codebone's indexing time,
and writes `HELPS`, `DOES NOT HELP`, `MIXED`, or `INCONCLUSIVE` to `results/VERDICT.md`.

## One-prompt run

Requirements:

- macOS 13+ on Apple Silicon;
- the current [codebone app](https://github.com/palusc/codebone/releases/latest) installed;
- an authenticated [Codex CLI](https://github.com/openai/codex) or Claude Code installation;
- Python 3.11+ and Git.

Open this repository in your coding agent and paste the complete contents of
[`RUN_BENCHMARK.md`](RUN_BENCHMARK.md):

> Run the repository's automated benchmark now. Execute `python3 benchmark.py` from the repository
> root, wait for both isolated trials to finish, then read `results/VERDICT.md`. Report the verdict,
> the four task scores, token difference, agent-time difference and first-run time including
> codebone indexing. Do not implement the Northstar tasks yourself; the benchmark runner launches
> clean agent sessions for them.

That is the only benchmark prompt the user needs to send.

You can also start it directly:

```bash
python3 benchmark.py
```

The runner detects Codex or Claude Code automatically. To pin the setup:

```bash
python3 benchmark.py --agent codex --model gpt-5.4 --runs 3
python3 benchmark.py --agent claude --model sonnet --runs 3
```

Use one paired run for a quick personal answer. Use at least three for a result you intend to
publish; the report uses medians.

Agent runs consume your existing CLI subscription or API allowance. They can execute commands
and edit the temporary sample projects. This runner does not install agents, authenticate accounts,
or change your codebone app's selected project. Prerequisites must already be configured.

## What this comparison actually measures

The codebone arm receives a **static context file** generated with codebone's deterministic
fallback provider and four fixed queries derived from the task. It does **not** measure live MCP
tool use, automatic query selection, local-model synthesis, or the full desktop app workflow.
Both arms have MCP disabled. Treat the verdict as a comparison of this prepared-context workflow,
not a verdict on every way to use codebone. The task-aware query selection is part of the treatment.

Fresh tokens exclude cached inputs and include outputs; this is not a monetary cost comparison.
Indexing is timed separately. Default models may change between CLI releases; pin `--model` when
comparing results. Codex ignores user config; Claude Code uses safe mode. Organization-managed
policies and built-in agent defaults can still affect a run.

## The project

`project/` is a generated Northstar Commerce SaaS monolith with:

- 160+ files across API, billing, customers, identity, payments, orders, catalog, inventory,
  fulfillment, subscriptions, support, analytics, notifications, organizations and audit;
- repository, service, API, policy, serializer, event and worker layers;
- a TypeScript operations console, migrations and architecture decision records;
- shared persistence and event infrastructure;
- historical documentation and migration files alongside the runtime code.

This is a compact generated sample, not a production-scale repository. File count alone does not
represent complexity. Every trial receives a new copy generated by
[`task/make_project.py`](task/make_project.py). The checker is stored outside those copies and its
hash is checked after the agent runs; this is a guard against accidental edits, not a security sandbox.

## The implementation task

Both modes receive the same four-part request:

1. update standard VAT across invoices, credit notes and finance exports;
2. carry an optional customer phone field through persistence, API and events;
3. repair the password-reset TTL unit mismatch;
4. make retried payment webhooks idempotent across the ledger and event bus.

The task crosses multiple layers and includes plausible false leads in migrations, docs and sibling
domains. [`task/check.py`](task/check.py) verifies behavior rather than looking for a particular diff.

## What is automatic

`benchmark.py` performs all of this without manual bookkeeping:

- generates two identical project copies;
- initializes clean Git histories;
- starts two fresh non-interactive agent sessions;
- builds the second arm's context from that exact copy using the installed codebone runtime;
- measures codebone indexing separately from agent work;
- captures agent-reported token usage when available;
- executes four behavioral checks outside the editable copies;
- stores raw JSON and generates a plain-English Markdown verdict;
- saves each completed arm immediately and reports failed or timed-out runs as inconclusive;
- removes temporary projects unless `--keep-workdirs` is used.

No token, duration or cost value is entered by hand.

## Verdict rules

Correctness wins over speed:

- **HELPS** — codebone completes more verified tasks, or both score 4/4 and measured agent work
  improves by at least 10% without a major regression.
- **DOES NOT HELP** — codebone completes fewer tasks, or equal 4/4 runs use at least 10% more agent
  work on every available efficiency metric.
- **MIXED** — both score 4/4 but the difference is below the decision threshold.
- **INCONCLUSIVE** — a run failed or neither mode reached 4/4.

The report shows both agent time and first-run time including indexing. A single run answers
“did it help me this time?”; it is not presented as universal independent validation.

## Validate the harness

Fast validation without spending model tokens:

```bash
python3 benchmark.py --dry-run
python3 -m unittest discover -s tests -v
```

Raw result history is written to `results/runs.json`; the readable answer is
`results/VERDICT.md`. Both are ignored by Git so a local run does not change tracked files.

To use a source checkout instead of the installed app, set `CODEBONE_REPO` to the repository
containing `src/service.py` and `CODEBONE_PYTHON` to the Python executable in its configured
environment. The generator accepts only new or empty output directories; it never deletes an
existing destination.
